## Estratégia: 4 Fases em 8 Semanas

### Fase 1: Segurança & Fundamentos (Semanas 1-2)
**Objetivo:** Garantir que a app é segura para dados reais de famílias.

#### 1.1 Corrigir vulnerabilidades de segurança (CRÍTICO)
**Ficheiros:**
- `supabase/functions/send-weekly-plan/index.ts` → Adicionar `verify_jwt=true`
- `supabase/functions/analyze-curriculum-coverage/index.ts` → Adicionar `verify_jwt=true`
- `src/contexts/AuthContext.tsx` → Validar que o client não chama essas functions diretamente sem auth
- `vercel.json` → Adicionar headers de segurança

**Ações:**
1. No Supabase Dashboard → Edge Functions → `send-weekly-plan` e `analyze-curriculum-coverage` → Ativar "Verify JWT"
2. Adicionar ao `vercel.json`:
```json
{
  "headers": [
    {
      "source": "/(.*)",
      "headers": [
        { "key": "X-Frame-Options", "value": "DENY" },
        { "key": "X-Content-Type-Options", "value": "nosniff" },
        { "key": "Referrer-Policy", "value": "strict-origin-when-cross-origin" },
        { "key": "Permissions-Policy", "value": "camera=(), microphone=(), geolocation=()" }
      ]
    }
  ]
}
```
3. Criar `supabase/functions/_shared/html-escape.ts` para sanitizar `familyName` nos emails
4. Atualizar `send-welcome-email/index.ts` e `invite-family-member/index.ts` para usar o escape

**Custo:** 0€
**Esforço:** 2-3h

#### 1.2 Variáveis de ambiente (BAIXO ESFORÇO)
**Ficheiros:**
- Criar `.env.example` com todas as variáveis documentadas
- Verificar `.gitignore` inclui `.env.local`

**Ações:**
1. Criar `.env.example`:
```
VITE_SUPABASE_URL=
VITE_SUPABASE_ANON_KEY=
```
2. Confirmar que `.env.local` está em `.gitignore` e fazer `git rm --cached .env.local` se necessário

**Custo:** 0€
**Esforço:** 15 min

#### 1.3 CORS lockdown (BAIXO ESFORÇO)
**Ficheiros:** Todas as 5 edge functions em `supabase/functions/*/index.ts`

**Ação:** Substituir `Access-Control-Allow-Origin: *` por `https://nexseed.pt` em todas as edge functions.

**Custo:** 0€
**Esforço:** 30 min

### Fase 2: Observabilidade & CI Básico (Semanas 2-3)
**Objetivo:** Saber o que está a acontecer em produção e evitar regressões.

#### 2.1 Sentry para Error Tracking (GRATUITO até 5K erros/mês)
**Ficheiros:**
- Instalar: `bun add @sentry/react`
- `src/main.tsx` → Inicializar Sentry
- `src/App.tsx` → Integrar Sentry ErrorBoundary
- `supabase/functions/*/index.ts` → Adicionar Sentry nas edge functions (via npm import)

**Ações:**
1. Criar conta gratuita em Sentry.io
2. Instalar `@sentry/react` e configurar em `src/main.tsx`:
```typescript
import * as Sentry from "@sentry/react";

Sentry.init({
  dsn: "YOUR_DSN",
  environment: import.meta.env.MODE,
  tracesSampleRate: 0.1,
});
```
3. Substituir o ErrorBoundary manual por `Sentry.ErrorBoundary` em `App.tsx`
4. Nas edge functions, adicionar error tracking básico

**Custo:** 0€ (plano gratuito)
**Esforço:** 2-3h

#### 2.2 CI/CD com GitHub Actions (SIMPLES)
**Ficheiros:**
- Criar `.github/workflows/ci.yml`

**Ação:** Criar workflow simples que corre lint + test + build em cada push/PR:
```yaml
name: CI
on: [push, pull_request]
jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: bun
      - run: bun install --frozen-lockfile
      - run: bun run lint
      - run: bun test
      - run: bun run build
```

**Custo:** 0€ (GitHub Actions gratuito para repos públicos ou privados com limite)
**Esforço:** 30 min

#### 2.3 Error Boundary + Toast melhorado
**Ficheiros:**
- `src/App.tsx` → Melhorar ErrorBoundary com info mais útil
- `src/hooks/` → Adicionar error toast genérico nos hooks que não tratam erros

**Custo:** 0€

## Recomendação Final

**Se só puderes fazer UMA coisa esta semana:** Corrigir a autenticação nas 2 edge functions. É o fix mais rápido e mais importante — sem ele, qualquer pessoa pode enviar emails ou executar funções de IA com as tuas credenciais.

**Se puderes fazer DUAS coisas:** Adicionar o Sentry. Saber o que está a falhar em produção é essencial antes de ter reais utilizadores.

**Se puderes fazer TRÊS:** Configurar o CI/CD. Garante que não quebras nada ao fazer deploy.

**Para o beta com 10-25 famílias:** A Fase 1 + Fase 2 são suficientes. A Fase 3 (validação, testes) é nice-to-have. A Fase 4 (Stripe) é necessária apenas quando quiseres começar a cobrar.

## Nota sobre o produto em si

O produto core é **muito sólido**. O planner AI com Gemini, a geração de PDFs, o email automático, o portfolio, os reports trimestrais — tudo isto é funcional e resolver dores reais. O problema não é o produto, é a camada de infraestrutura por cima.

As dores que o NexSeed resolve são reais:
1. **Famílias homeschooling em Portugal precisam de planos curriculares** → O planner AI resolve
2. **Precisam de documentação para a escola âncora** → Os reports trimestrais resolvem
3. **Precisam de organizar atividades e progresso** → O diário e portfolio resolvem
4. **Querem metodologias pedagógicas estruturadas** → As 14 metodologias resolvem

O que precisas não é de mais features — é de **confiança** (segurança, monitoring) e **monetização** (Stripe) para poder cobrar.
