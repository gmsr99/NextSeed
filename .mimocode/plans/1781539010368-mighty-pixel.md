# Análise e Sugestões de Melhoria — NexSeed

## O que achas desta aplicação?

### Pontos Fortes

1. **Conceito de produto sólido e bem definido**
   - O loop `Planejar → Fazer → Registar → Provar` é o modelo mental correto para o público-alvo (pais sem formação pedagógica)
   - O output em PDF imprimível é uma decisão acertada — a semana corre offline, em papel, na mesa da cozinha
   - A modelação de metodologias (catálogo + princípios + atividades-modelo + matriz de compatibilidade + `ai_generation_style`) é o ativo diferenciador mais defensável

2. **Stack técnica moderna e bem escolhida**
   - React + Vite + TypeScript + Tailwind + shadcn/ui — ecossistema maduro
   - Supabase como backend — boa escolha para MVP, permite iterar rápido
   - Gemini 2.5 Flash via edge function — chave no servidor, seguro

3. **Funcionalidades diferenciadoras**
   - Alinhamento automático pré-escolar/primário (a mesma hora, disciplinas diferentes)
   - Mini-séries de leitura (4 episódios sequenciais semanais)
   - Suporte multi-criança com idades diferentes
   - Integração com currículo nacional DGE (589 conteúdos)

4. **Qualidade de código**
   - ErrorBoundary implementado
   - Lazy loading em todas as rotas
   - Testes unitários para o gerador de plano
   - Organização clara de componentes

---

### Sugestões de Melhoria

#### 🔴 Prioridade Crítica (antes de qualquer coisa)

**1. Segurança — Edge Functions e Storage**
- Edge functions `generate-weekly-plan` e `invite-family-member` têm `verify_jwt=false`
- Bucket `activity-photos` é público e permite listagem (fotos de menores!)
- Funções `SECURITY DEFINER` executáveis por `anon`
- **Ação:** Autenticar todas as edge functions; tornar o bucket privado com policies corretas

**2. Motor de IA duplicado**
- `supabase/functions/generate-weekly-plan/index.ts` (server-side, desatualizada)
- `src/lib/geminiPlanner.ts` (cliente, atual)
- **Ação:** Consolidar num único ponto server-side; remover a duplicação

**3. Currículo duplicado em ≥4 sítios**
- BD (`curriculum_contents`, `curriculum_disciplines`, `nexseed_curriculum`)
- `src/data/curriculos/*.json`
- `src/lib/curriculo_2ano_portugal.json`
- `curriculo_2ano_portugal.json` (raiz)
- Pasta `curriculos/` (raiz)
- **Ação:** Fonte única = BD; eliminar cópias estáticas

#### 🟡 Prioridade Alta

**4. Simplificar a navegação**
- Sidebar com ~20 entradas em 5 grupos é confusa para novos utilizadores
- Reduzir para os 4 verbos: **Planear · Fazer · Registar · Provar**
- Motor Criativo → integrar como funcionalidade dentro do planeador (não como página de 1º nível)

**5. Onboarding obrigatório**
- Após registo, o utilizador cai num dashboard vazio
- "Time to first plan" tem de ser < 10 minutos
- Criar wizard guiado: perfil criança → metodologia → interesses → 1º plano gerado

**6. Remover mocks e rotas mortas**
- Forum (`/forum`), Comunidade e Formação para Pais estão disabled mas acessíveis
- Não lançar com conteúdo falso alcançável

**7. Melhorar cobertura de testes**
- Apenas 6 ficheiros de teste para uma app com 29 páginas
- Falta testes para: hooks, edge functions, autenticação, PDFs
- Adicionar testes de integração para o fluxo completo (gerar → guardar → enviar)

#### 🟢 Prioridade Média

**8. Performance e bundle**
- Muitos Radix UI components importados — verificar quais são realmente usados
- Considerar code splitting mais agressivo
- PWA para uso offline (já planeado na FASE 3)

**9. Consistência de tipos**
- `children.school_year` é texto livre → usar enum ou constraint
- `time_slot` como string → considerar tipo mais restritivo
- Adicionar `UNIQUE` constraint em `weekly_plans (family_id, week_start)`

**10. UX de geração de plano**
- Adicionar progresso visual durante a geração (já existe `generatingStep`, mas pode ser mais rico)
- Permitir regenerar atividades individuais (não apenas o plano completo)
- Adicionar undo/redo no editor de plano

**11. Acessibilidade**
- Verificar contraste de cores (alguns textos `text-muted-foreground` podem ser difíceis de ler)
- Adicionar labels ARIA onde faltam
- Suporte para screen readers

**12. Documentação**
- README está bom mas falta documentação de API interna
- Adicionar JSDoc nas funções públicas
- Documentar o protocolo de edge functions

#### 🔵 Melhorias Avançadas

**13. Analytics e observabilidade**
- Integrar Sentry para tracking de erros
- Adicionar analytics leves (Plausible ou similar)
- Monitorizar uso de IA (tokens, latência, erros)

**14. Modelo de negócio**
- Implementar trial de 14 dias
- Subscrição mensal por família
- Feature gating para funcionalidades premium

**15. Internacionalização**
- Atualmente tudo em PT — mas preparar para i18n caso haja expansão
- Usar `react-i18next` ou similar

---

### Resumo Executivo

A NexSeed tem um **produto sólido com um loop de valor completo** e uma **stack técnica bem escolhida**. Os principais riscos são de **segurança** (edge functions abertas, bucket público) e de **complexidade percetiva** (demasiadas portas de entrada para um utilizador novo). 

Recomendação: **completar a FASE 1 (segurança) antes de qualquer coisa**, depois **simplificar a navegação e adicionar onboarding** (FASE 2), e só depois pensar em features novas.
